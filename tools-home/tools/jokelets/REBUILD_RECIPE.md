# Rebuildable jokelets

A jokelet is a versioned production with original ingredients and an edit recipe. The finished mix is one output. It must remain possible to change a single effect, music track or video and render a new version without generating the joke again.

## Required record

| Ingredient | Preserve |
| --- | --- |
| Identity | Canonical joke ID and aliases; production ID/version; parent recipe; approvals and automation review separately. A rebuild remains the same joke. |
| Script | Exact cued input sent to the voice provider, including tags, punctuation and capitalization; spoken text separately; script version/hash and delivery notes. Do not reconstruct the input from captions. |
| ElevenLabs | Original downloaded voice bytes and durable location/hash; take/history ID; voice/model ID, settings, generation date, attempts and cost when available. A service history link alone is insufficient. |
| HeyGen | Original render bytes and durable location/hash; render/job ID; exact input voice hash, avatar/reference, prompt and settings. Keep failed/rejected attempts distinct. |
| Picture and reaction | Original sources and derivatives; IDs/hashes, source ranges, frame convention, stabilization, crop/scale/motion, timing and muted/retained audio. |
| Ambient, music, each effect | Separate original file and durable location/hash for every layer, including repeated instances; stable layer ID, timeline start, source in/out, gain, fades, ducking, loop/rate/pan, routing and processing. Store intentional defaults explicitly. Do not infer missing levels or timings from a finished mix. |
| Captions and graphics | Separate text/cue or image sources, fonts/style/version, placement, timing and transforms. A burned-caption export is a publication derivative. |
| Edit and engine | Portable Factory/Publication/SxLock project as applicable; exact tool/version, timebase, transforms, export dimensions/FPS/codec and dependencies. Keep a clean intermediate and later publication layers separate. |
| Outputs and evidence | Output bytes/location/hash; parent recipe hash; full-playback approval; restore/rebuild test result, reviewer/date, known gaps. |

Use stable file IDs/repository paths and hashes rather than temporary downloads or expiring media URLs. Save provider originals and portable projects in production storage. Do not include credentials, login codes or API keys in recipes or public source records.

## Working record

Factory media details now offer `sourceTrail` fields for exact cued script, ElevenLabs take/history reference, original voice file, HeyGen render, rebuild project and missing-source notes. These are discovery pointers, not proof that all source bytes are accessible. Full track-level settings belong in the linked portable edit/mix project. Existing archive metadata is retained alongside these fields.

New Factory manual-wizard `production` manifests retain selected source-record snapshots, clip source ranges, mute decisions and linked audio IDs. They do not automatically fill missing provider provenance or acquire missing audio stems. Cleanliness is no longer asserted solely because the manual wizard produced the file. Human approval must be followed by the separate clean-source review for automatic reuse.

There is not yet a universal importer that accepts every stage's recipe and rebuilds the entire production unattended. Use the actual stage projects; record unsupported transformations and handoffs. Do not call a jokelet rebuild-ready until its source links, bytes, settings and recovery path have been checked.

## Replacing one ingredient

1. Load the saved production by ID/version and check its canonical joke against the ledger. Open its original edit/mix project; do not start a new-joke generation job.
2. Verify source hashes and settings. If a required ingredient is missing, mark the gap and resolve it before claiming a faithful rebuild. Keep the finished output available for manual use as appropriate.
3. Copy to a new recipe version with a parent reference. Replace only the selected layer/source; record the old/new IDs and the reason. Retain all other settings, deliberate timing and original files.
4. Render affected stages and check the whole result. A replacement video/voice can affect sync and duration; an effect/music replacement can affect levels, fades and ducking. Record any necessary dependent changes.
5. Save the new project, changed ingredient, intermediate/output files and hashes. Keep prior versions. Reassess editorial approval and automatic source eligibility independently.

Rebuild verification means the saved inputs/projects can reproduce the intended edit. It does not imply byte-identical exports across encoders or re-generating an identical AI performance. Reuse original generated bytes whenever only downstream edits change.
