# SxLock R25 media repair — October 28, 2026

Status: implemented and locally tested on `fix/sxlock-media-integrity-20261028`, starting at main `5154f84a8d78faf8caee841ad2247dc7ba4f7b04`. **Not deployed. Historical red-cast origin and physical Android acceptance remain open. Captions remain suspended.**

## Findings grounded in code and controlled exports

- `sxlock.js::videoExport` previously decoded the source into an RGB canvas, captured it using `setInterval`/`requestFrame`, started MediaRecorder before `video.play()`, and held the final frame for another 120 ms. The selected FPS was a timer target, not a CFR timeline. MP4 duration finalization only repaired headers; it did not repair sample timestamps, encoder delay, dropped/duplicated pictures or colour conversions.
- The old encoder requested 6 Mbps below 1080 width or 10 Mbps above it, with 256 kbps audio. It always reencoded the picture, including sound-only edits. The first codec choice hardcoded AVC baseline level 3.1; generic MP4 could choose another codec. Original dimensions were the default, with a separate 720-width preview option. There is no CRF setting or active FFmpeg export endpoint in this path.
- `aspectlock/index.html`'s `Q('render').onclick` also uses a canvas and real-time capture, but prefers VP8/WebM, 540×960, 25 fps target, 3.5 Mbps video and 128 kbps audio. It was inspected as the known-good reference. Copying that capture implementation would retain conversion, compression and timer risks, so AspectLock itself is unchanged.
- Controlled four-second full-range BT.709 input: old generic MP4 selected VP9/Opus on this Linux browser; an additional AVC/Opus diagnostic isolated its H.264 video path without native AAC. The old AVC output lasted about 4.194 s, used nonuniform timestamps and changed the transfer tag to sRGB. At the sampled static frame, RGB MAE was 2.248/255 and PSNR 38.245 dB. These establish unnecessary reencoding, colour-metadata change and timing padding, **not reproduction of the owner's specific red cast**. The desktop encoder retained full-range BT.709; recovered `17618.mp4` instead signals limited-range SMPTE170M/BT470BG. That platform/provenance difference is unresolved.
- Recovered `17484.mp4`: 1667 frames, exact 25 fps, 66.680 s. `17618.mp4`: 1674 frames, 66.913233 s with uneven PTS. Their matching audio differs by a constant 136 ms in the sampled windows. Approximate matching-picture delays vary by 1–3 frames. Their exact originating app/version is not independently established; filenames alone are not provenance.

## Implemented correction

- New `export-engine.mjs::exportVideo`: demux original media, preserve encoded H.264 packets and decoder colour configuration for compliant original-size CFR exports, mix soundtrack/effects independently in 48 kHz OfflineAudioContext chunks, then mux synchronized H.264/AAC MP4. No canvas, preview, MediaRecorder or wall-clock timer is used for sound-only picture export. A no-change compatible MP4 is copied byte-for-byte.
- Original soundtrack PCM is assembled from decoded **presentation timestamps**, retaining positive gaps and trimming negative priming samples. It is never concatenated around effects. A 96 MiB decoded-audio guard limits phone memory; the no-op path requires no soundtrack decode. Clipping fails explicitly rather than silently normalizing.
- Placement/loop calculations use integer 48 kHz sample indices. Newly inserted or explicitly moved cues snap to the selected source frame grid; unedited legacy cue times and project schema remain preserved. At 25 fps F863 is 34.520 s and sample 1,656,960. The PCM regression checks its exact placement in the 32–40 s render chunk.
- Native AAC is capability-checked directly. The pinned local fallback emits a 1024-sample priming lead-in with its sequential packet timestamps; fallback-only negative start PTS lets the MP4 edit list compensate it. A real-file correlation test caught and corrected this before delivery. The UI and direct module imports are both covered, including globally registered fallback detection. Native AAC's own timing is retained.
- If requested size/FPS/container requires picture encoding, samples are processed offline on explicit timestamps using quality mode, quantizer 18 and a bitrate fallback. HDR requiring conversion is refused until a validated SDR master is supplied. These are distinct from the lossless sound-only path.
- Automatic final checks cover frame count, every video PTS, duration, dimensions, audio duration and copied colour metadata. Added regression workflow runs on future SxLock changes. Existing R24 workspace layout, library IDs, recording and approved assets are preserved; UI identity is R25 review, cache identifier 27.
